\textbf{TradeActor} \hfill Mar. 2026 -- Present \titlebreak
Built a research pipeline for \textbf{stock forecasting and portfolio policy learning}, covering multimodal signal generation, VLM-based forecast evaluation, teacher-label construction, policy training, and backtesting. The system focuses on \textbf{DOW-20} equities, combines historical price charts, numerical summaries, and news windows into prediction samples, and trains a \textbf{Qwen}-based portfolio policy to predict daily target allocations across \textbf{cash + 20 stocks}.
\begin{itemize}[nosep, topsep=\intraProjectListTopSep]
    \item \textbf{Forecast sample generation}: Constructed rollout samples for \textbf{DOW-20} stocks from historical price charts, numerical summaries, and news windows; called \textbf{Qwen/Gemini} models to produce structured \textbf{JSON} signals including upside probability, 24-day return quantile, long/short/flat trading stance, and confidence.
    \item \textbf{VLM signal evaluation}: Measured \textbf{valid rate, 5/10/24-day directional accuracy, probability error, quantile coverage}, and bias\_strength buckets to assess forecast quality; found that aggregate signals were weak, while high-bias\_strength subsets offered useful filtering value.
    \item \textbf{Teacher-label construction}: Used future \textbf{5d/10d open returns} as the main lookahead-oracle signal and blended in VLM direction and confidence as a lightweight adjustment, generating daily \textbf{21-dimensional target allocations} for portfolio policy supervision.
    \item \textbf{Portfolio policy training}: Used \textbf{Qwen3.5-0.8B} as the portfolio-state encoder, feeding current holdings and VLM JSON signals for 20 stocks; attached an \textbf{FFN head} to the \textbf{<PORTFOLIO\_DECISION>} token to output 21-dimensional softmax allocations optimized with a utility-oriented loss over return, turnover cost, and allocation-change cost.
    \item \textbf{Backtesting validation}: Integrated the policy into the \textbf{StockBench} backtesting framework as a \textbf{qwen\_portfolio\_policy strategy}, enabling trained policies to predict daily target weights, generate buy/sell orders, and validate the full path from predictive signals to executable portfolio decisions.
\end{itemize}

\textbf{TimeThinkingLLM} \hfill Sep. 2025 -- Jan. 2026 \titlebreak
Developed a time-series reasoning framework for \textbf{Time-Series QA}, bridging continuous temporal signals and natural-language reasoning. The project combines a \textbf{Temporal Encoder + LLM Backbone} architecture with reconstruction loss, VLM knowledge distillation, and \textbf{RLVR/GRPO} reinforcement learning to improve LLM perception and reasoning over trends, anomalies, periodicity, and other temporal patterns.
\begin{itemize}[nosep, topsep=\intraProjectListTopSep]
    \item \textbf{Model architecture}: Designed and implemented an \textbf{MLP-Mixer}-based \textbf{temporal encoder} with token mixing, channel mixing, statistical feature injection, and learnable positional encodings, mapping continuous time series into semantic embedding spaces compatible with LLMs such as \textbf{Qwen-3}.
    \item \textbf{Modal alignment and training}: Built a \textbf{dynamic embedding injection mechanism} that inserts temporal features into text-instruction sequences; introduced a trend-aware reconstruction loss based on \textbf{Pearson Correlation} so alignment emphasizes sequence shape and directional movement instead of isolated pointwise error.
    \item \textbf{Reasoning enhancement}: Established a four-stage training pipeline covering \textbf{modal pretraining, joint fine-tuning, CoT supervised fine-tuning, and GRPO reinforcement learning}; used \textbf{VLMs} to generate chain-of-thought data for trend analysis, anomaly detection, and periodicity judgment.
    \item \textbf{Experimental evaluation}: Conducted systematic evaluation on \textbf{ChatTS Eval A/B, TimeSeriesExam, MCQ}, and other time-series understanding and reasoning benchmarks; analyzed encoder convergence, model-capacity limits, and CoT stability to guide later data expansion, VLM-as-a-Judge reward modeling, and backbone migration.
\end{itemize}

\textbf{CUARewarder} \hfill Mar. 2026 -- May 2026 \titlebreak
Built an automated trajectory-evaluation and reward-modeling pipeline for \textbf{GUI Agents}. Given a task goal, screenshot sequence, agent action history, and optional reasoning traces, the system uses \textbf{VLMs} and multiple judge backends to determine whether an agent truly completed a web or desktop task, then emits structured reward outputs for agent evaluation, reward modeling, and RL data construction.
\begin{itemize}[nosep, topsep=\intraProjectListTopSep]
    \item \textbf{Trajectory data processing}: Designed and implemented a batch processing pipeline for \textbf{GUI Agent} trajectories, standardizing screenshot sequences, action histories, task goals, and reasoning or operation notes into unified model inputs.
    \item \textbf{Automated evaluation module}: Built a \textbf{VLM}- and judge-backend-based trajectory evaluation mechanism that jointly considers screenshot-state changes, action paths, and task-completion requirements to assess real completion quality in complex interaction scenarios.
    \item \textbf{Reward signal generation}: Converted judge outcomes into structured \textbf{judge/reward outputs}, capturing process quality and task completion more accurately than traditional evaluation methods based only on final text answers or string matching.
    \item \textbf{Core deliverable}: Completed a reusable evaluation loop covering \textbf{trajectory collection, screenshot understanding, action-history analysis, and reward generation}, supporting future Agent Benchmarks, reward modeling, and RL training-data construction.
\end{itemize}
